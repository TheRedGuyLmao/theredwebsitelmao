# Чарник ИАБ — как это устроено и настроено

Где что лежит:

```
seek_and_destroy/sheet/index.html   страница
seek_and_destroy/sheet/app.js       вход, создание персонажа, лист игрока, панель мастера
seek_and_destroy/sheet/rules.js     ПРАВИЛА: планеты, вера, навыки, очки. Меняйте здесь.
worker/index.js                     Worker сайта: отправляет запросы /seek_and_destroy/sheet/api/... на сервер
worker/sheet-api.js                 сервер чарника: вход, игроки, листы
wrangler.jsonc                      настройки Worker (имя, хранилище, какие адреса идут на сервер)
.assetsignore                       файлы, которые сайт не отдаёт посетителям
```

Сайт theredwebsite.com работает как Cloudflare Worker: файлы из репозитория отдаются как раньше,
а Worker запускается только для адресов `/seek_and_destroy/sheet/api/...`. Листы лежат в **Cloudflare KV**.

## Вход

Обычный логин и пароль, без почты.

- **Мастер** входит под логином `мастер` с паролем из секрета `GM_PASSWORD`.
- **Игроков создаёт мастер** в своей панели: «Новый игрок» → логин и пароль (пароль предлагается сам).
  После создания появится окно со ссылкой, логином и паролем — кнопка «Скопировать всё», и отправьте игроку.
- Забыл пароль — откройте игрока → «Сменить пароль». Старый пароль и старые входы перестанут работать.
- «Удалить игрока» удаляет и его вход, и лист.
- Вход держится 30 дней. После 10 неверных паролей подряд логин блокируется на 15 минут.
- Пароли хранятся только в виде хэша: прочитать их нельзя даже из хранилища.
- Если сменить `GM_PASSWORD`, все игроки разлогинятся (пароли у них останутся прежние).

Если открыть страницу без сервера (например, просто файл с диска), она работает в демо-режиме:
всё хранится в браузере, вверху переключатель «Игрок / Мастер».

## Настройка (один раз)

1. **Хранилище KV** — уже создано, ID вписан в `wrangler.jsonc`.
2. **Пароль мастера:** Worker `theredwebsitelmao` → **Settings** → **Variables and Secrets** → **Add**:
   имя `GM_PASSWORD`, тип **Secret**, значение — ваш пароль. Секрет применяется сразу.
3. **Cloudflare Access не нужен.** Если приложение Access на `theredwebsite.com/seek_and_destroy/sheet` создано —
   удалите его (Zero Trust → Access → Applications), иначе поверх входа будет ещё и вход по почте.
   Переменные `ADMIN_EMAILS`, `TEAM_DOMAIN`, `POLICY_AUD` больше не используются — их можно удалить.

## Проверка

Откройте `https://theredwebsite.com/seek_and_destroy/sheet/` → форма «Вход» → `мастер` и ваш пароль →
список игроков. Создайте тестового игрока, войдите под ним в другом браузере (или в режиме инкогнито).

Если видно «Не задан пароль мастера GM_PASSWORD» — шаг 2 не сделан.
Если вместо формы входа переключатель «Игрок / Мастер» — сервер не отвечает, смотрите Worker → **Logs**.

## Проверка на компьютере

Нужен Node.js. Создайте в корне репозитория файл `.dev.vars` (он в `.gitignore`):

```
GM_PASSWORD=test
```

и запустите `npx wrangler dev`. Можно добавить `DEV_LOGIN=мастер` — тогда пускает без пароля.
**Никогда не задавайте DEV_LOGIN на сайте.**
